# Design Document: Include an execution report of the ReviewBot at the end of the review

## 1. Background

When `ReviewBot` performs a review, it sometimes operates under constraints, such as reaching the maximum number of iterations or being "forced" to finish by the turn-warning mechanism. Currently, the user is unaware of these execution details. Providing a brief execution report at the end of the Markdown review will improve transparency, helping users understand if the review was comprehensive or if the bot was cut short.

## 2. Goals

- Inform the user if the bot reached the maximum turn limit or was forced to finish.
- Provide a summary of the bot's activities (number of turns, tool calls, and success rate).
- Append a brief "Execution Report" section to the final `review_md` generated by `ReviewBot`.

## 3. Proposed Changes

### 3.1 `BaseBotSession` Enhancements (`api/bot/base_session.py`)

- **Iteration Tracking**: Add `self.iterations_used: int = 0` and `self.timed_out: bool = False`.
- **Termination Tracking**: Add `self.finished_via_terminal_tool: bool = False`.
- Update the `run()` loop to:
    - Increment `iterations_used` at each step.
    - Set `finished_via_terminal_tool = True` upon a successful terminal tool call.
    - Set `timed_out = True` if the loop completes without a terminal call.

### 3.2 `ReviewBot` Tool Update (`api/reviewbot/tools.py`)

Update the `save_review` tool to append an execution report to the `review_md` string.

#### Execution Report Generation logic:
1.  **Retrieve Stats**: Get summary stats using `session.get_summary_stats()`.
2.  **Determine Status**:
    - `Status: ✅ Complete` (if `session.finished_via_terminal_tool` is True and `iterations_used` < `max_iterations`).
    - `Status: ⚠️ Forced` (if `session.finished_via_terminal_tool` is True but the bot received a "last turn" warning).
    - `Status: 🛑 Timed Out` (if `session.timed_out` is True).
3.  **Summarize Log**: Extract a brief list of tool calls from `session.conversation_log`. Format: `Turn X: tool_name (Result)`.
4.  **Append to Markdown**: Add a thematic break (`---`) and the report section at the end of the review.

### 3.3 Example Report Format
```markdown
---
### 🤖 ReviewBot Execution Report
- **Status**: ✅ Complete
- **Turns**: 12 / 50
- **Tool Success Rate**: 100%
- **Activity Log**:
  - Turn 2: tree (Success)
  - Turn 4: grep (Success)
  - Turn 6: read_source_file (Success)
  - Turn 8: save_review (Success)
```

## 4. Implementation Plan

1.  **Modify `BaseBotSession`**: Add state variables for iteration and termination tracking.
2.  **Update `BaseBotSession.run()`**: Logic to update the new state variables.
3.  **Refactor `save_review`**: 
    - Implement a helper function `_generate_execution_report(session)` to build the Markdown string.
    - Append the result of the helper to `review_md` before saving to the database.
4.  **Verification**:
    - Add a unit test in `test_reviewbot_tools.py` that mocks a session and verifies the report is appended.
    - Test the "Forced" and "Timed Out" conditions by mocking the session state.

## 5. Design Decisions

- **Brief log only**: To keep it brief, only `role="tool"` turns will be listed in the Activity Log section of the report.
- **Always Append**: The report will be appended to every review. If the user finds it too verbose, we can later add a toggle, but for now, transparency is prioritized.
- **Privacy**: Since `conversation_log` already prunes/shortens content, the execution report is safe to include in the task record.
