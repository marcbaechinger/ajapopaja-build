# Design Document: Include an execution report of the ArchBot at the end of the design document

## 1. Background

Similar to `ReviewBot`, `ArchBot` also operates under turn constraints. When it generates a design document, it's beneficial for the user to see a summary of the bot's execution process, especially if it was nearly out of turns or reached the limit. This transparency helps in evaluating the depth of the generated design.

## 2. Goals

- Provide a brief execution report at the end of design documents generated by `ArchBot`.
- Indicate the execution status (Complete, Forced, or Timed Out).
- Summarize the tools used during the session.

## 3. Proposed Changes

### 3.1 Shared Execution Report Utility (`api/bot/utils.py`)

To avoid duplication between `ReviewBot` and `ArchBot`, a shared utility function `generate_execution_report(session)` will be created.

**Logic**:
- Accepts a `BaseBotSession` instance.
- Retrieves summary stats.
- Constructs a Markdown section summarizing:
    - Status (based on `finished_via_terminal_tool` and turn warnings).
    - Turn count.
    - Tool success rate.
    - A brief Activity Log (tool names and results).

### 3.2 `ArchBot` Tool Update (`api/archbot/tools.py`)

Update the `save_design_doc` tool:
- Import `generate_execution_report` from `api.bot.utils`.
- Append the report to the `design_doc_md` string before persisting it.

### 3.3 `BaseBotSession` Enhancements (Already covered in ReviewBot design)

The same enhancements to `BaseBotSession` (iteration tracking, termination tracking) will support both bots.

## 4. Implementation Plan

1.  **Modify `BaseBotSession`**: (Shared step) Add state variables and update the `run()` loop.
2.  **Create `api/bot/utils.py`**: Implement `generate_execution_report`.
3.  **Update `ArchBot` tools**: Integrate the report generation into `save_design_doc`.
4.  **Verification**:
    - Add a unit test in `test_archbot_tools.py` verifying the report is appended to saved design documents.

## 5. Design Decisions

- **Consistency**: Both bots will use the same report format for a unified user experience.
- **Briefness**: The activity log will be limited to a few lines to ensure it doesn't distract from the main content.
